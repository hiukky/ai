## Commits without being asked

`commit` commits when a unit of work is done, not when someone remembers to
ask. Done means all three:

1. A complete step: a feature, a fix, a task. Not half a function.
2. It builds and the fast tests pass.
3. Nothing unrelated is mixed in. If it is, the commit is split first.

It holds off while the approach is still being discussed, or when you said to
wait.

```text
<type>[scope][!]: <description>
```

`feat` · `fix` · `docs` · `style` · `refactor` · `perf` · `test` · `build` ·
`ci` · `chore` · `revert`. The type comes from the diff, not from how the task
was named. The body says why, and is left out when the change explains itself.

## Pushes, but never forces

A commit is pushed right after. These always ask first: `--force` and
`--force-with-lease`, a push to a protected branch, anything that rewrites
pushed history.

## Pull requests

The title is a Conventional Commit line; the branch follows gitflow.

| Branch | For |
| --- | --- |
| `feature/` | a new capability |
| `fix/` | a bug fix |
| `hotfix/` | an urgent fix from the production branch |
| `release/` | release preparation |
| `chore/` `docs/` `ci/` `refactor/` | maintenance |

`fix/123-hook-stop-shape`, not `fix/123`. A working branch like `agent/<id>`
is renamed before it is published.
