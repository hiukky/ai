## Everything goes through the dotfiles

Installing or configuring anything means writing it into the chezmoi source,
then letting `chezmoi apply` do it. `apt install`, `npm i -g` or `curl | sh`
are fine to try something out; the task is done only when a clean machine
would get the same thing from an apply.

`sync` reads your setup before touching it: where the source lives, how it is
organized, what its own `AGENTS.md` decided. Your conventions win over the
skill's. Then it puts the change where that kind of change belongs:

| Change | Goes to |
| --- | --- |
| OS package | the existing package list |
| runtime | the version manager's config |
| tool with an installer | a guarded `run_once_` script |
| app on the host machine | the host's script |
| config file | `chezmoi add`, a template when it varies per machine |
| caches, credentials | nowhere |

## "Is it in sync?"

Four questions, not one:

1. **Machine vs source**: `chezmoi status`
2. **Source vs committed**: `git status` in the source
3. **Committed vs pushed**
4. **Installed vs provisioned**: what is on the machine that nothing installs

Before every apply it reads the diff for **removals**: a `PATH` line an
installer appended to your shell rc disappears on the next apply unless it
moves into the source.

## Disk space

`reclaim` measures, frees what rebuilds itself, and leaves the rest to you.

```bash
reclaim scan                          # measure: Linux, WSL disks, Windows host
reclaim prune docker|caches|build     # only what regenerates
reclaim compact                       # prints the WSL compaction, never runs it
```

Worktrees, volumes, models and VM images are listed for you to decide one by
one. Compaction is printed, not run: `wsl --shutdown` would stop the agent
running it.
