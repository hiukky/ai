## A video is a spec

One `demo.yml`, next to the video it makes, says everything: what the video
shows in order, the sandbox it is recorded in, the files the app works on, and
how it is cut. To change the video, edit the file and run it again.

```bash
tui-record init     .demo/demo.yml   # scaffold a spec
tui-record validate .demo            # check it
tui-record beats    .demo            # read it back as prose
tui-record seed     .demo            # build the sandbox and fixtures
tui-record probe    .demo            # try a selector against the live app
tui-record run      .demo            # record, cut, scan, render
tui-record recut    .demo            # cut and render the last take again
```

The key-by-key format is in `references/spec.md`.

## What it guarantees

- **Never your machine.** The take runs in a sandbox with its own `HOME`,
  prompt and git identity. Your username and paths never reach the screen.
- **Every gesture is checked.** A step that did nothing aborts the take instead
  of shipping a video where the app looks broken.
- **Waiting is cut, not skipped.** A build or a model answer is shortened to a
  fixed span. No frames are dropped, so nothing renders blank.
- **Nothing leaks.** Before a video is handed over it is scanned for usernames,
  hostnames, tokens, keys and private IPs, and redacted without shifting a
  single character on screen.
